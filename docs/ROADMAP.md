# 路线图：Aicho Muse

## M0 — 设计验证（当前）

目标：把"语音创作缪斯"讲清楚、跑通核心交互。

- [x] 项目命名与品牌定位（Aicho Muse / 声创）
- [x] 产品设计、架构、人设声色、路线图文档
- [ ] 可交互打字原型：单会话 + 一个预设人设 + 简单项目概念
- [ ] 验证核心对话体验：提问式引导是否让用户写得更顺畅

**验收**：陌生用户拿到原型，无需说明就能完成一次"口述一小段经历 → 得到提问与鼓励"。

## M1 — MVP（Web）

目标：可日常使用的单用户 Web 应用。

- 响应式 Web + PWA 基础
- 账号系统（邮箱登录）
- 打字对话，SSE 流式输出
- 3–4 个预设人设 + 人设编辑器
- 语音回复：接入至少一家 TTS，可播放/倍速
- 创作项目：新建、章节编辑、自动保存
- 导出 Markdown
- 基础限流与隐私说明

**验收**：用户能创建自定义人设，完成一个 3–5 章的短篇或自传初稿，并导出为 Markdown。

## M2 — 语音闭环

目标：语音成为与打字平等的主流输入方式。

- 语音输入：STT 接入（优先中文识别质量）
- 全链路语音对话（说 → 转写 → 回复 → 朗读），支持打断
- 项目结构增强：大纲、人物卡、时间线、灵感碎片箱
- 写作工具：润色、扩写、续写、风格迁移
- 回复类型可观测（提问/反馈/建议/鼓励 的统计与调优）
- 版本历史与回退

**验收**：用户可以在通勤路上用语音口述一整章，回家后在电脑上继续完善。

## M3 — 智能增强与生态

目标：让助手"记得你"，并支持更丰富的创作生态。

- RAG 长期记忆：偏好、设定、人物关系跨会话延续
- 声音克隆（授权制）与情绪化 TTS
- [x] 多人设团队模式（编辑 + 读者 + 导师 同时陪跑，作品绑定团队 + 会话切换）
- 一致性检查（人物/时间线/设定冲突提醒）
- 导出 PDF / DOCX；云端多设备同步
- [x] 社区分享：人设与音色搭配（公开库 + 一键收藏克隆）

**验收**：三个月后重新打开一个旧项目，助手仍然记得关键设定与用户的写作偏好。

## 后续探索（非承诺）

- 桌面 / iOS / Android 封装
- 团队协作创作
- 基于创作数据的"个人写作报告"（风格偏好、高频主题）
- 多语言创作（中英日等）

## 里程碑决策点

每个里程碑结束前需要确认：

1. 核心指标是否达标（如"引导后用户继续创作的对话占比"）。
2. 语音质量是否达到"愿意听完整段回复"的水平。
3. 人设一致性是否稳定（换设备、换会话后体验一致）。
4. 成本是否可控（token 与 TTS 单用户月成本）。
