# 系统架构：Aicho Muse

## 1. 总体架构

```text
┌───────────────────────────── 客户端 ─────────────────────────────┐
│  Web / PWA（响应式）                                              │
│  React + TypeScript + Tailwind                                   │

│  ├─ 项目/章节编辑器                                               │

│  └─ 语音：MediaRecorder（录音）/ Web Speech API（播放兜底）        │
└──────────────────────────────┬───────────────────────────────────┘
                               │ HTTPS / WebSocket
┌──────────────────────────────▼───────────────────────────────────┐
│  API 网关 / BFF（Go + Gin）                                       │
│  ├─ 认证与会话                                                   │
│  ├─ 对话流（流式输出）                                           │
│  ├─ 项目/文档服务                                                │
│  ├─ 人设/声色服务                                                │
│  └─ 语音代理（STT/TTS 路由与缓存）                                │
└──────────────────────────────┬───────────────────────────────────┘
        ┌──────────────────────┼──────────────────────┐
        ▼                      ▼                      ▼
┌───────────────┐   ┌───────────────────┐   ┌────────────────────┐
│ AI 编排层      │   │ 语音服务层         │   │ 数据层              │
│ 角色提示词组装 │   │ STT 适配器         │   │ PostgreSQL（用户/   │
│ 工具调用/流程  │   │ TTS 适配器         │   │  项目/章节/人设）   │
│ 多提供商抽象   │   │ 音色库/缓存        │   │ Qdrant（记忆 RAG）  │
└───────┬───────┘   └─────────┬─────────┘   │ Redis（会话/缓存）   │
        │                     │             │ 对象存储（音频）      │
        │                     │             └──────────────────────┘
```

## 2. 客户端（Web / PWA）

- **框架**：React + TypeScript + Vite（或 Next.js），Tailwind CSS。
- **响应式**：移动端优先，桌面端增强；PWA 支持安装与离线基础缓存。
- **语音采集**：`MediaRecorder` 录音上传；桌面端可加 Web Speech API 兜底。
- **音频播放**：流式播放 TTS 音频（audio 标签 + Web Audio），支持倍速。
- **状态**：聊天流式渲染（SSE/WebSocket）、本地草稿、离线队列。

## 3. 后端服务（Go + Gin）

与既有 Aicho 技术栈保持一致，便于团队经验复用与代码互借。

- **认证与会话**：账号系统（邮箱/OAuth），JWT + Redis 会话。
- **对话服务**：WebSocket/SSE 流式对话；请求内组装角色上下文，调用 LLM。
- **项目服务**：项目/章节/大纲的 CRUD、版本历史（快照或 diff）、导出。
- **人设服务**：人设卡 CRUD、预设库、人设校验与版本化。
- **语音代理**：统一 STT/TTS 接口，后端持密钥，前端不接触厂商凭据。

## 4. AI 编排层

这是"创作教练"的灵魂，职责：

1. **上下文组装**：系统提示（人设卡 + 行为准则）+ 项目上下文（大纲/当前章节/人物卡）+ 记忆检索 + 最近对话。
2. **行为约束**：引导优先、代写需用户显式请求；反馈要具体、可执行、有鼓励。
3. **工具调用**：查询/更新项目、保存灵感、检索记忆、调用润色工具。
4. **可观测**：记录每次对话的角色配置、token 用量、反馈类型，用于调优。

### 提供商抽象

```text
type ChatProvider interface {
    ChatStream(ctx, messages, params) (stream, error)
}
```

支持 OpenAI 兼容接口为主，预留国内模型（如 DeepSeek、通义、豆包）接入位，按配置路由。

## 5. 语音服务层

统一接口，厂商无关：

```text
type STTProvider interface { Transcribe(ctx, audio, lang) (text, error) }
type TTSProvider interface { Synthesize(ctx, text, voiceProfile) (audio, error) }
```

- **STT**：优先支持中文的云端识别（Whisper / 火山引擎 / 通义），保留本地 Whisper 自托管选项。
- **TTS**：火山引擎、Fish Audio、OpenAI TTS；支持音色参数映射（语速/音调/情感）。
- **音色缓存**：相同文本 + 相同音色参数的结果缓存，降低延迟与成本。
- **声音克隆**：M3 里程碑，走 Fish Audio 等克隆服务，需用户授权与合规说明。

## 6. 数据层

| 存储 | 用途 |
| --- | --- |
| PostgreSQL | 用户、项目、章节、人设卡、对话记录（元数据）、订阅 |
| Qdrant | 记忆向量检索：用户偏好、作品设定、灵感碎片 |
| Redis | 会话状态、流式缓冲、限流、缓存 |
| 对象存储 | 音频文件、导出文件、用户上传的参考素材 |

## 7. 关键流程

### 对话创作流程

```text
用户输入（文字/语音）
  → 语音则先 STT 转文本
  → 后端组装上下文（人设 + 项目 + 记忆 + 历史）
  → LLM 流式生成回复
  → 前端流式显示文本
  → 可选：TTS 合成语音 → 播放
```

### 语音回复优化

- 长回复截断/分段合成，先让用户听到开头，后续续播。
- 语音用"口语化改写"（不改变内容）保证自然度。
- 支持打断：用户说话时停止播放并开始倾听。

## 8. 安全与隐私

- 创作内容加密存储（AES-GCM，密钥与数据分离）。
- 语音数据仅用于实时转写，可配置"不保存音频"。
- 厂商调用最小化：仅发送当前请求所需上下文。
- 敏感信息脱敏；导出与分享前提供内容审查提示。
- 完整的账号删除与数据清除流程。

## 9. 部署

- 首选容器化：Docker Compose 起步（API + Web + Postgres + Qdrant + Redis）。
- 生产：云服务器 / Vercel（前端）+ 容器（后端），域名挂在 aicho.chat 子域或独立子域（如 muse.aicho.chat）。
- 环境通过 `.env` 配置，密钥不入库。
